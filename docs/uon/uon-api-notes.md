# U-ON Travel API — Заметки

Документация: https://api.u-on.ru/doc
Версия: REST API v1

## Аутентификация

API ключ встраивается прямо в URL:
```
https://api.u-on.ru/{API_KEY}/method.json
```

Где получить ключ: **Настройки → Интеграции → API → Включить**

Формат ответа: `json` или `xml` (суффикс в URL).

Лимит: **не более 10 запросов/секунду** → sleep(110ms) между запросами.

---

## Ключевые методы

### Клиенты (`/user`)

| Метод | URL | Описание |
|-------|-----|----------|
| Список | `GET /user.json` | Список клиентов |
| Поиск | `GET /user.json?phone=375...` | По телефону |
| Поиск | `GET /user.json?email=...` | По email |
| Создать | `POST /user/create.json` | Новый клиент |

**Поля клиента:**
```json
{
  "u_name": "Иван",
  "u_surname": "Иванов",
  "u_phone": "+375291234567",
  "u_email": "ivan@example.com",
  "u_birthday": "1990-01-15"
}
```

---

### Заявки (`/request`)

| Метод | URL | Описание |
|-------|-----|----------|
| Одна заявка | `GET /request/{id}.json` | По ID |
| Список | `GET /request-list.json` | С фильтрами |
| Создать | `POST /request/create.json` | Новая заявка |
| Обновить | `POST /request/update/{id}.json` | Изменить |

**Параметры фильтра `/request-list`:**
```
page            — номер страницы (default: 1)
per_page        — записей на страницу (max: 100)
created_date_from — YYYY-MM-DD
created_date_to   — YYYY-MM-DD
status_id       — ID статуса
manager_id      — ID менеджера
```

**Ключевые поля заявки:**
```json
{
  "r_dat": "2026-01-15",          // дата создания
  "r_dat_end": "2026-01-20",      // дата закрытия
  "r_status_name": "Оплачена",    // статус
  "manager_name": "Даша",         // менеджер
  "r_price_netto": "1500.00",     // сумма (без комиссии)
  "country_name": "Турция",       // направление
  "r_tourist_count": 2            // количество туристов
}
```

**Статусы (типичные для тур. агентства):**
- Новая
- В работе
- Ожидает оплаты
- Оплачена
- Выполнена
- Отменена

### Создание заявки

```json
POST /request/create.json

{
  "u_id": 123,               // ID клиента (обязательно или r_user_*)
  "r_dat": "2026-01-20",     // дата создания
  "r_status_id": 1,          // ID статуса "Новая"
  "manager_id": 5,           // ID ответственного менеджера
  "r_country": "Таиланд",    // направление
  "r_dat_begin": "2026-03-01", // дата начала тура
  "r_dat_end": "2026-03-14",   // дата конца тура
  "r_tourist_count": 2,
  "r_note": "Из Instagram. Интересует пляжный отдых, семья 2 взрослых"
}
```

## Типичные сценарии

### Проверка — новый клиент или повторный?

```javascript
// 1. Поиск по телефону
GET /user.json?phone=375291234567

// Если массив пустой → НОВЫЙ клиент
// Если есть записи → ПОВТОРНЫЙ, берём u_id для запроса истории

// 2. Последний тур повторного клиента
GET /request-list.json?u_id=123&per_page=1&page=1
// Сортировка по дате — берём первый результат
```

### Создание нового лида из Instagram

```javascript
// 1. Создать клиента
POST /user/create.json
{ "u_name": "Имя из Instagram", "u_phone": "..." }
// → получаем u_id

// 2. Создать заявку
POST /request/create.json
{
  "u_id": <u_id>,
  "r_status_id": 1,    // "Новая"
  "manager_id": <кто нажал "Взять в работу">,
  "r_note": "Источник: Instagram Direct. Запрос: ..."
}
```

## Известные особенности

- Поля в ответе могут различаться в зависимости от версии U-ON и настроек аккаунта — **всегда проверяй реальный ответ**
- Поле цены: `r_price_netto` (без комиссии), `r_price_brutto` (с комиссией)
- Телефон передавать **без пробелов и скобок**, в формате `375291234567` или `+375291234567`
- Дата в формате `YYYY-MM-DD` или `DD.MM.YYYY` — уточнять по реальным ответам API
- При создании заявки без `u_id` можно передавать `r_user_name`, `r_user_phone` — U-ON создаст клиента автоматически
